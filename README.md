# 心臓のアトリエ

個人の趣味として、人間の心臓を回して眺め、構造を楽しむ3Dモデルを作るプロジェクト。
最終成果物は単一のHTML。
設計、実装、検証はChatGPTとClaudeが交代して担当する。

## 開き方

`index.html`をダウンロードしてWebGL対応ブラウザーで開く。
コードとライブラリは内蔵しており、モデル表示にネット接続は不要。
参考リンクを開く場合だけネット接続が必要。
iPhoneのSafariは、端末に保存したHTMLを開けない。2026-11-07に、claude.aiの非公開ページに置いたものをiPhoneのSafariで開き、表示を確認した（「検証状況」。過去の記録は[docs/validation/verification-history.md](docs/validation/verification-history.md)）。iOSのファイルプレビューや他社のHTML表示アプリでの動作は未確認・対象外（Issue #9）。
プレビューアプリではなくブラウザーでの表示を対象とする。

- ドラッグ／タッチで回転、スクロール／ピンチで拡大縮小。
- 部位ボタンまたはモデルのクリックで部位を選択。
- 「外観」「刺激伝導系」を切り替えて観察。
- 刺激伝導系では「前へ」「次へ」で電気刺激の経路を順に確認。
- 前面、背面、身体の左側へボタンで移動。
- モデルにキーボードフォーカスを移すと、矢印キーで回転、＋／−で拡大縮小、Homeで前面へ戻る。

## 現在の版と範囲

v0.5は、BodyParts3Dの成人男性1体の心臓と周囲の血管を外観とし、刺激伝導系の模式表示と、断面による内部表示に、拍動・血流・心音の模式表示を加えた試作（v0.4は拍動・血流・心音を含まない。画面の版表記は2026-11-14にv0.4から更新した）。
2026-11-07のユーザー判断で、v0.2までの手作りの概形（球と管）を廃止し、BodyParts3Dの形状に置き換えた。

外観では心房、心室、大動脈、肺動脈、大静脈、肺静脈、冠動脈、冠静脈を選択できる。
心房・心室の境界は自動推定で、実際の境界とは一致しない。
形状は1体分のデータで、個人差や拍動による変化は表さない。

刺激伝導系は洞房結節、心房への広がり、房室結節、ヒス束の近位区間と分岐区間、右脚、左脚、プルキンエ線維を説明する独自形状。ヒス束の2区間は別々に選択でき、左脚側の起始目印と右脚側の起始目印を分けている。右脚と左脚は別々に選べ、色も分けた。右脚は1本の線、左脚は幅のある近位部と前・中隔・後ろの3方向の線で模式表示する。左脚の分かれ方には変異があり、全員共通の固定3本を示してはいない。
BodyParts3Dに刺激伝導系の形状はないため、周囲の構造から位置を推定した（「刺激伝導系の配置」参照）。
心房への広がりは破線で表し、独立した神経や血管と混同しないようにする。
太さは説明用に誇張している。刺激の伝わりは拍動と同じ時計で表示し、4つの区間の時間（約50・100・25・75ミリ秒）はOpenStaxの本文に合わせる。区間の中の進み方と模式心電図の波の形・大きさは表示用で、実測ではない（「刺激の伝わりと模式心電図」参照）。

内部（断面）では、前後方向の平面で心臓を切り、内腔の面、壁の切り口、弁、乳頭筋を見せる（2026-11-07、ユーザー判断で案Aを採用。「内部観察の表示方式の比較」参照）。
断面の位置はスライダーで前後に動かせる。断面は心臓に固定し、回転すると切り口を斜めから見られる。
選択できるのは心房・心室、僧帽弁、三尖弁、大動脈弁、肺動脈弁、乳頭筋。
「刺激伝導系を重ねる」を押すと、刺激伝導系も同じ断面で切って重ね、選べるようになる（初期状態はオフ）。
切り口の面は心臓の壁にだけ作る。血管は元データに壁の厚みがない薄い殻なので、切ると内腔が見え、切り口の面は作らない（冠動脈・冠静脈・肺静脈は閉じた形だが、同じ扱いにしている）。
弁と乳頭筋はBodyParts3D 4.0の形状で、弁の開き具合は元データの1時点のもの。
元データの乳頭筋は右心室の3つと左心室の外側乳頭筋（前外側の頭を含む）だけで、左心室の後ろの乳頭筋はない（OpenStax 19.1では左心室に前と後ろの2つ）。画面の説明にもそう書いた。
拍動は説明用の模式表示で、「拍動を再生」で動く（初期状態は停止。「拍動の模式表示」参照）。血流は「血流」モードで、経路に沿う粒子として模式表示する（初期状態は停止。「血流の粒子」参照）。内部（断面）では「血流を重ねる」で、粒子を断面に重ねられる（初期状態はオフ。「断面への血流の重ね表示」参照）。「心音を鳴らす」で、拍動に同期する説明用の合成心音を鳴らせる（初期状態はオフ。「心音の合成と同期」参照）。刺激伝導系では、拍動を再生すると刺激の伝わりと模式の心電図が同じ時計で動く。血流では、部位を選ぶとそこを通る経路の粒子を強調する（「血流モードの経路強調」参照）。
医療用途ではない。
各機能の節には実装時点の未確認事項も残している。今回の終了判定と追加確認の結果は「検証状況」の「残タスクの追加確認」を優先する。

## 進め方

1. 外観試作：回転と拡大縮小、主要部位の選択。
2. 最初の完成版：資料との形状照合、外観の改善、部位説明と操作の調整。
3. 内部観察：内腔と弁を表せるモデル構造を検討してから実装。v0.4で断面表示を実装した。
4. 動き：血流方向と説明用の拍動を追加（段階B：刺激の伝わり、模式心電図、血流の経路強調は2026-11-14）。拍動（段階1）、血流の経路の生成（段階2、データのみ）、経路に沿う粒子を拍動に同期させて透過表示で見せること（段階3）、血流表示用の模式弁尖（案C）を実装した。断面への重ね表示（段階4）も、粒子だけを重ねる形で実装した。

まずPCで確認し、スマートフォンでも操作しやすくする。
見栄えの良さと、主要部位の位置とつながりを説明できることを目標にする。
刺激伝導系の模式表示はユーザー指定の参考資料を受けて追加したが、内部構造の完成を意味しない。

## 参考資料と外部素材の採用方針

参考文献、参考サイト、参考3Dモデルは、無料かつ会員登録・ログイン不要で必要な内容を閲覧できるものに限定する。
外部素材を取り込む場合は、データの取得も同じ条件を満たすものに限る。
有料素材、登録・ログイン必須の資料、無料体験への登録が必要な資料は採用しない。
ユーザーが明示的に方針変更するまで、この条件を維持する。

無料閲覧は、モデルや画像の複製・改変・再配布の許可を意味しない。
参考に読む場合と、HTMLやリポジトリに素材を取り込む場合を区別し、後者ではライセンスと出典を確認する。

### 刺激伝導系の検証範囲（現在、2026-11-09更新。2026-11-08、main `838e984`からの変更を含む）

AIが交代したときの重複調査と完了判断の誤りを防ぐため、現在の範囲をここ1か所にまとめる。詳細な数値は「検証状況」の各項目と、[過去の確認記録](docs/validation/verification-history.md)にある。過去の記録には対象の版を付けている。

- 位置が解剖学的に妥当かは、**確認していない**。
- 房室結節とヒス束は、資料の文章が述べる局所解剖（コッホの三角の頂点、無冠尖・右冠尖の下の中隔の頂）を手がかりに置き直した（2026-11-07、ユーザー判断）。現行形状の[図6Aとの描画比較](docs/references/conduction-figure6a-validation-2026-11-08.md)では、前面投影で三弁の大まかな並びと、大動脈弁に対するヒス束の大まかな上下関係を確認した。モデルの診断画像では、房室結節側から左脚側、右脚側へ続く表示上の接続を確認した。左右脚の近位方向は判定保留で、右脚が向かう乳頭筋は標本0059と異なる。
- **組織位置の定量照合は未実施で、今後の作業対象外**（「設計判断」）。現行モデルが使う部品では緻密房室結節の末端、膜性中隔の下縁、ヒス束の貫通部と分岐部の境界を同定できず、文献と同じ測定点を置けない（BodyParts3D全体の部品は検索していない）。図6Aとの比較で得たのは模式表示の観察結果で、各部位の解剖学的位置は未確認。この対象外は照合の完了ではない。
- 局所解剖との対応（下の表）。資料はStephensonら（2017）とChenら（2025）の本文。コッホの三角の境界はWikipedia「Koch's triangle」による（三次資料。原典は有料で未確認）。

| 房室結節 | 伝導系はコッホの三角の頂点から始まる（Stephenson p.7、Tawaraの記述と一致とある）。三角の底は冠静脈洞口、辺は三尖弁中隔尖の付け根とトダロ腱、頂点は中心線維体のそば | 中隔尖の付け根のうち無冠尖に最も近い点。トダロ腱と中心線維体はデータにないため、頂点の近似。無冠尖まで10.3mm | 周辺構造を使った近似で、組織の末端としては未同定。旧規則（洞口と付け根の中心の中点）は洞口から頂点までの0.34の位置で、頂点から16.5mm離れ、対応していなかった |
| ヒス束の近位区間 | 結節から前方・わずかに上へ進む（Stephenson Fig.3の説明）。房室伝導軸は後上方から前下方へ進む（Chen §3.1）。貫通束は膜性中隔の下縁に沿って前方へ（Chen §3.5）。資料ごとの対象区間を区別する | 房室結節側から左脚側の目印までを直線で結ぶ模式表示。左へ18.2mm、下へ4.5mm、後ろへ2.0mm（直線） | 前後の符号は両資料の「前方」と逆。下向きはChen §3.1の「前下方」と一致するが、Stephensonの「わずかに上」とは異なる。候補範囲4→5mmで前後の符号が反転する。対象区間も未対応で、傾きだけを原因とは決められない（下の再計測） |
| 左脚側の起始目印 | ヒス束は右冠尖の下（Chen）。分岐束は右冠尖の最下点から6.5mm（Stephenson、1心）、無冠洞は分岐束から約6mm未満、右冠洞は約8mm（Chen） | 無冠尖・右冠尖の最下点に最も近い、左心室側の中隔の点。無冠尖まで4.7mm、右冠尖の最下点まで5.2mm | 弁の近くを選ぶ規則で、距離の近さは検証にならない。左脚の起始範囲との対応は未確定。右脚の起始目印は別の点へ分離した |

### 左脚の幅と3方向の模式表示（2026-11-08）

main `27401be`の左脚1本を、近位部の面と前・中隔・後ろの3方向の経路へ変更した。
[変更前後の投影図](docs/validation/left-bundle-fan-2026-11-08.png)は、実際に生成した三角形を前面と上方から描いたもの。資料の図を転載した画像ではない。

Stephensonら（2017）の図5（PDF p.7）を閲覧し、幅のある近位部と3方向に広がる研究例を参考にした。
一方、[The normal variants in the left bundle branch system（2017）](https://pubmed.ncbi.nlm.nih.gov/28341304/)の無料・登録不要の抄録は、前・後の主分枝と変異のある中隔枝を記載する。こちらは抄録のみの確認で、全文は未取得。
このため、固定の3本が全員にあるという説明は改め、研究例に基づく模式表示と明記した。

面は既存の左心室側中隔候補点に吸着させた4行×5列の点から作り、つぶれた面・重複面を除く。
広がる方向は周囲の候補点から求め、横方向への変位の上限4.5〜7.5mmは表示用の値で、論文の実測幅ではない。
結果は12頂点・12三角形。両面から描画し、左脚の1部位としてまとめて選択する。
従来の中央経路を中隔方向に使い、追加する前・後方向は既存の左心室プルキンエ経路の制御点へつなぐ。
後ろの乳頭筋は元データにないため、そこへの付着は作っていない。面の位置・幅、分束境界、経路の解剖学的な正しさは未検証である。

データ形式を5へ更新した。心臓の壁・弁・血管など15部品、ヒス束、右脚、既存のプルキンエ経路は変更していない。
テストでは、面の連結と退化・辺の共有、ヒス束側との接続、各経路の心室側と既存網への接続を検査する。
単体テスト32件、ビルド、同じ元zipからの再生成でのバイナリ・HTMLの一致を確認した。これらは生成処理の回帰検査であり、医学的な位置の検証には使わない。
ブラウザーのテストでは、PC幅1440pxとスマートフォン幅390pxで左脚を選び、前面・左側面を画像として保存する。

### ヒス束の2区間と、左右脚の別々の起始（2026-11-08、PR #25時点）

説明用の模式配置として、ヒス束を2区間に分け、独立したボタン・色・ラベルを付けた。
近位区間から分岐区間へ進み、左脚は手前側の起始目印から出て、右脚は分岐区間の先の別の起始目印から続く。
左右脚を同時に1点から分ける構成を改めた。

| 区間・目印 | 作り方 | 表していないこと |
|---|---|---|

### 刺激伝導系モデルの修正（2026-11-08、PR #23）

前節の調査に続き、生成処理と描画形状を変更した。
房室結節と脚の分岐点は動かしていない。ヒス束の前後方向の食い違いは未解決で、今回の形状変更を解剖学的な位置の検証とみなさない。変更後のヒス束の長さは18.854mm（両端を結ぶ直線）で、旧制御点の折れ線長20.686mmと区別する。

- ヒス束：左心室側の中隔頂点への吸着をやめ、推定した両端を直線で結ぶ模式形状にした。旧経路は房室結節から次の制御点まで約12.8mm移動し、その後に曲がっていた。貫通部の組織形状を持たないデータに対し、左心室表面の経路として描く扱いを取り除いた。
- 右脚：前半を中隔候補面、後半を右心室内腔の表面に沿ってサンプリングする。乳頭筋側の終点は中隔候補面の外にあるため、後半まで同じ候補面へ吸着させない。旧処理は途中までを表面から求めた後、終点だけを追加しており、最後の制御点間隔が約28.4mmあった。新処理では終点までの経路を求め、制御点間隔の最大値は約8.5mmとなった。ヒス束との接続点とプルキンエ線維との接続点を保持する。中隔縁柱は元データにないため再現していない。
- 心房への広がり：最寄りの表面点への吸着でずれていた両端を、洞房結節、房室結節、左心房側の目印に固定する。右心房側は房室結節から約4.0mm手前で終わっていた。破線の模式表示という意味は維持する。
- 洞房結節：上記の細長い楕円体へ変更。主部の長さと幅だけを1標本から参考にし、分界稜沿いの不規則な形や突起は再現しない。
- ヒス束のラベル：制御点の配列の中央ではなく、描画曲線の長さの中点に置く。2点になった経路の終点へラベルが偏らないようにした。

[変更前後の投影図](docs/validation/conduction-model-2026-11-08.png)で、メッシュを前面と上面へ投影し、ヒス束の曲がりの解消、右脚後半の経路、洞房結節の細長い形を目視確認した。これはThree.jsが生成した三角形を別の描画系で投影する確認で、実際のビューアのWebGL表示や断面操作の確認とは区別する。
左右の脚の本数（左脚も1本）、プルキンエ線維の本数、各目印を決める近似規則は残っている。

検証：元zip2件のSHA-256は記録と一致。再生成後も15部品の頂点と面は変更前とバイト単位で同じ。ビルド、Nodeの30テスト、差分の空白検査が成功。追加した2テストは旧データで失敗し、結節との接続、右脚の制御点間隔、ヒス束の曲がり、洞房結節の縦長形状を検査する。解剖学的な位置の正しさを保証するテストではない。ローカルのChromiumは引き続き起動できず、実機操作は未確認。

### BodyParts3D試作の作り方（2026-11-07）

4.0の心臓には心室の心筋（壁）のメッシュがなく、心室は内腔、弁、乳頭筋だけだった。
そのため心臓の壁は3.0の「wall of heart」（1メッシュ、約13万面）を使う。
壁を約2.7万面へ減らし、各三角形を最も近い4.0の心腔（左右の心房・心室）に割り当てて区分けした。
前面では、右心室と左心室の推定境界が前室間枝（冠動脈）の走る位置とほぼ一致することを画面で確認した。

各部位の出どころ（IDは`scripts/prepare-bodyparts3d.mjs`の`parts`）：

- 3.0：心臓の壁（FMA7274）、大動脈の本体3部品（FMA3736、FMA3768、FMA3784）、大静脈（FMA4720、FMA10951）。3.0のファイルには名称の記載がなく、大動脈・大静脈との対応は既存の記述に従っており、名称の照合は未了。
- 4.0：肺動脈幹と左右の肺動脈、肺静脈、冠動脈・冠静脈（名称で選択）、大動脈弓の3本の枝（腕頭動脈FJ3417、左総頸動脈FJ3483、左鎖骨下動脈FJ3479）、弁尖11個、乳頭筋5個。
- 4.0の心腔（左右の心房・心室の内腔、FJ2422〜FJ2425）は表示しない。壁の区分けと刺激伝導系の位置の計算にだけ使う。
- 刺激伝導系の位置の計算には、さらに4.0の上大静脈（FJ3645）、左右の心房の壁（FJ2438、FJ2439）を使う（表示しない）。冠静脈洞（FJ2655）は、2026-11-07の置き直しで使わなくなった。

4.0の部品は同じ3.0の部品より10mm低い位置にある（上大静脈、右冠動脈、冠静脈洞で確認）ため、4.0側を10mm上げて合わせる。
補正しないと冠動脈が心臓表面から外れる。
この補正は単体テストで検査する。
大動脈の本体は4.0で形が作り直されていて差が一定でないため3.0を使い、弓部の3本の枝だけ4.0から足す（枝は別メッシュで、弓に「つながる」とは、頂点どうしが0.6〜2.4mmまで近いことを指す。単体テストで検査）。
血管は心臓の近くで平面に沿って切る。

### 内部観察の表示方式の比較（2026-11-07）

「進め方」3の内腔と弁の表示方法を、実装前に比較した。
断面（案A）を推奨し、2026-11-07にユーザーが採用した。

元データを調べた結果は次のとおり。

- 3.0の心臓の壁は、外面と内面を持つ閉じた形状。4.0の心腔の表面と壁の内面は、中央値0.1mmで一致する（10mm補正後、各心腔の中心から60方向に光線を当てて測定）。

### 心音の合成と同期（2026-11-13、Issue #31）

「心音を鳴らす」（初期はオフ）で、拍動に合わせた説明用の合成心音を鳴らす。音量スライダー付き。ユーザーの承認（2026-11-08のIssue、2026-11-13の設計案）にもとづく。音質より、音と動きのずれがないことを優先した。

- **対応**：Ⅰ音は心室の収縮の始まり（拍動の100ms）、Ⅱ音は心室の弛緩の始まり（370ms）。房室弁の閉鎖とⅠ音、動脈弁の閉鎖とⅡ音という説明（[NHLBI：拍動の仕組み](https://www.nhlbi.nih.gov/health/heart/heart-beats)）に合わせたもので、弁の形状が動くことは表さない。時刻は`heartbeat.mjs`の`cycle`から計算し、数値を重ねて持たない。
- **音**：外部音源なし。三角波の短い音（Ⅰ音90Hz・0.14秒、Ⅱ音130Hz・0.1秒、音程が少し下がる）を、Web Audioで生成する。周波数と長さは表示用に決めた値で、聴診音の再現ではない。三角波の上の倍音は、小さなスピーカーでも聞こえるようにするため。速度を変えても音の長さは変えず、鳴る間隔だけが変わる（ゆっくり再生ではⅠ音→Ⅱ音が1.35秒、Ⅱ音→次のⅠ音が2.65秒）。
- **共通の時計**：拍動の位置は再生用の時計から読み、音は同じ時計から「拍動の位置→時刻」を計算して予約する。初めて音をオンにしたタップで、時計の元を`performance.now()`から音声処理の`currentTime`へ、今の拍動位置のまま切り替える（拍動は先頭へ飛ばない）。オフにすると時計の元を戻す。音のオン／オフでは位置も予約済みの音の計算も変わらず、過去の音をさかのぼって鳴らさない。
- **予約**：2秒先までを予約し、50msごとのタイマーで補う（描画が遅れても予約は続く）。予約を0.5秒先までにしていた初版は、CI（PR #44）で、拍動の開始から約1.5秒の前後に音が欠ける失敗が2件出た（原因のページの停止は特定していない。ローカルでは再現しなかったが、CPUを埋めた状態の試験で別の不具合を見つけた）。停止がどれだけ続いても欠けないわけではなく、予約より長い停止では音を捨てる。止める、速度の切り替え、画面を離れる／戻る、音のオン／オフのたびに、予約済みの音を短い減衰で止めて破棄し、今の位置から組み直す（二重発音と鳴り残りを防ぐ）。予約が過去になった音（0.04秒を超える遅れ）は、まとめて鳴らさず捨てる。
- **止めるときの位置**（2026-11-13、レビュー対応）：止める操作と画面を離れる操作では、時計を最後に描いた位置へ戻さず、時計の現在位置まで描画（壁・粒子・時期の表示）を進めてから止める。最初の版は最後の描画位置へ巻き戻していたため、最後の描画から停止までに鳴った音を、再開時に予約し直して二重に鳴らした。音声が中断された場合も、止まった時計の位置から続ける。3D表示が失われた（WebGLのコンテキスト喪失）ときは、拍動・音・予約のタイマーを止める。操作部品が無効になり、ページから止められないため。
- **遅延の補正**：音声処理が報告する出力遅延（`outputLatency`、なければ`baseLatency`、上限0.5秒）の分だけ音を早く予約し、画面が拍動位置に達する時刻に音が聞こえるようにした。**この値が各端末で正しいか、Safariがこの値を返すかは未確認**（MDNへ接続できず確認できなかった）。Bluetooth機器などの遅延まで含めた完全な同期は保証しない。
- **画面を離れたとき**：拍動と音を一緒に止め、戻ると同じ位置から再開する。離れていた間の音は鳴らさない。「視覚効果を減らす」では1拍分だけ予約し、終了とともに音も止まる。
- **音声が中断されたとき**：音声処理が`running`以外になると、心音をオフにして「音声が中断されたため、心音を切りました」と表示し、拍動は同じ位置から続ける（音声の時計が止まっても拍動が止まらない）。もう一度押すと再開する。Issueの「音だけ、または動きだけが取り残されない」を、この形で解釈した。
- **確認したこと**：`tests/heartsound.test.mjs`（単体）が、Ⅰ音・Ⅱ音の拍動位置（100・370ms）、ゆっくり再生と実際の速さでの予約時刻、時計の元の切り替えで位置が変わらないこと、遅延の早め予約、遅れた予約を捨てること、1拍だけの再生の終了、偽の音声処理での予約・取消し・音量を調べる。さらに、模擬時間で10分間、不規則な描画の遅れ（最大1秒）に、速度の切り替え・音のオン／オフ・停止と再開をランダムに混ぜても、聞こえる音がすべて100msか370msの位置にあり、二重に鳴らず、最短間隔が実際の速さの0.27秒を下回らないこと。`tests/viewer.spec.js`（Chromium）が、音の初期オフ、タップまで音声処理を作らないこと、タップ後の最初の音が拍動の続き（第2音）になること、予約の間隔がゆっくり再生で1.35秒・2.65秒になること、速度を切り替えた後の二重発音がないこと、止めた後に予約が増えないこと、音をオフにしても拍動が続くこと、非表示で拍動と音が止まること、音声処理の中断でオフに戻ること、「視覚効果を減らす」で1拍ごとにⅠ音・Ⅱ音が1回ずつであること、`AudioContext`がない場合にボタンが隠れること、幅390pxで画面内に収まることを調べる。ブラウザーテストは、`AudioContext`の差し替えで予約を記録するもので、実際の音は聞いていない。

### 血流の経路（2026-11-08、段階2。データの生成。画面での使い方は次の「血流の粒子」）

血液の実際の流線ではない。血管と心腔の中央を通り、弁の口の中心を結ぶ、説明用の模式の線。段階3で、この線に沿って粒子を動かした。
データは`meta.flow`（形式6）。`scripts/prepare-bodyparts3d.mjs`が内腔と弁と血管から計算する。

- 経路は6本。右心系は、上大静脈と下大静脈から、右心房、三尖弁、右心室、肺動脈弁、肺動脈幹を通り、左右の肺動脈へ進む。左心系は、4本の肺静脈（左上・左下・右上・右下）から、左心房、僧帽弁、左心室、大動脈弁、上行大動脈を通り、大動脈弓へ進む。
- 上大静脈を左肺動脈へ、下大静脈を右肺動脈へつなぐ割り振りは表示用で、実際の血流の対応ではない。肺静脈は、左の枝を合わせて切ると断面の中心が管の外へずれるため、各静脈の最も長い1部品（幹）だけを使った。支流は含まない。
- 各経路は約3mm間隔の78〜92点で、`marks`に4つの目印（心房の中央、房室弁の口、心室の中央、動脈弁の口）の点番号を持つ。`valves`は4つの弁の口の中心と半径。
- 作り方：血管は断面の重心をたどる。心腔は、内腔に収まる最大の球の中心。弁の口の中心は、弁尖の頂点のうち、弁の両側の心腔に4mm以内で接する点の平均（僧帽弁は5mm、半月弁は心室に2.5mm以内）。この「接する範囲」で中心と半径が変わるため、表示用の値で、実測の弁輪ではない。端は血管の切断面で閉じていないため、両端10mmを除いた。曲がりは平滑化40回で和らげ、弁の口の中心は動かさない。
- 4つの内腔（心房・心室の4.0のFJ2422〜FJ2425）は、画面に表示しない部品としてデータに入れた。生成時と単体テストが同じ内外判定を使うため。データは587,206→661,006バイト、`index.html`は1,417,728→1,516,128バイト。それ以外の部品のバイナリと刺激伝導系の座標は、変更前と一致した。

検査（生成時と`tests/flow.test.mjs`が同じ関数`scripts/flow-geometry.mjs`を使う）：

- 1mmごとに、内腔の中か、血管の殻のどれか1つの内側で、その殻の面まで3次元の最短距離で1mm以上あるか、のどちらかであること。血管は殻ごと（連結成分ごと）に判定し、切断端は検査用に閉じる（閉じた面は壁として数える）。重なった殻の内側にある別の殻の面は、その殻の中の点だけに効く。どちらでもない区間は、最大10mmで、弁の中心から8mm以内か、血管と心腔をつなぐ所に限る。通る心腔の順は、右が右心房→右心室、左が左心房→左心室。
- 測定結果：どちらでもない区間は、弁の根元の3〜5mm（肺動脈弁、僧帽弁、大動脈弁）と、右上肺静脈が左心房の壁を貫く6mmだけ。壁と弁の根元の周りにメッシュがなく、元データに開口がないため。
- 判定が失敗することも検査する：経路を15mmずらしたもの、左右を取り違えたもの、上大静脈の始点から左心房への直線、離れた12本の管の中心の空点（どの管にも入っていない）、壁から0.5mmの点（接線に直交する光線では2.18mmと出た）は、いずれも失敗する。
- 弁の口の中心は、弁尖の頂点から3mm以内（実測0.6〜1.8mm）、両側の心腔の内腔の頂点から10mm以内（実測で最大8.9mm）にあり、自分の心腔のほうが他より近い。

限界（未解決）：

- 血管の端10mmは経路に含まない。粒子はその内側で出入りする。
- 拍動に追従させる必要がある。同じ変位（`createBeat`の`displace`）を経路・内腔・血管・弁の中心に掛けると、全経路が内側に残る。経路を静止時の座標のままにすると、心房の収縮の最大で6本中1本、心室の収縮の最大で6本中2本が、この検査から外れる（単体テストの出力）。段階3では、粒子の位置を毎フレーム`displace`で動かした。

描画：血管・壁・内腔を半透明にして経路を重ね、正面・背面・左側面と、前額断（z=85より後ろ）を撮って目視した（`docs/validation/blood-flow-routes-2026-11-08.png`、クラウドのChromium、SwiftShader）。経路が管や心腔の外へ出る所は見つからなかった。半透明の重ね描きは奥行きを判別しにくいため、最終的な判定は単体テストによる。

### 血流の粒子（2026-11-08、段階3）

「血流」モード（`04 / FLOW`）で、経路（`meta.flow`）に沿う粒子を、拍動と同じ時間軸で動かす。壁は刺激伝導系モードと同じく透かし（2026-11-14に不透明度0.12から、中を0.07・縁を明るくする描き方へ変更。「PC幅の画面構成と見た目」参照）、粒子は不透明に描く。青は右心系の経路、赤は左心系の経路で、色は識別用（酸素の量を表すものではない）。心房・心室・血管は、外観と同じく選べる。初期状態は停止で、「拍動を再生」を押すと動く（自動では始めない）。速さは拍動と共通で、初期は5倍にゆっくり、「実際の速さ」で1拍0.8秒になる。
血液の実際の流線でも速度でもない。弁は、血流を見せるための模式の弁尖を描く（次の「血流の模式弁尖」）。元データの弁尖と経路が交差する問題（「血流の経路」の限界）は、この画面では元の弁尖を描かないことで避けており、解決ではない。

粒子の動かし方（`src/flow.mjs`）：

- 1本の経路は、粒子が輪になって並ぶ。血管の出口に着いた粒子は、入口から入り直す（両端12mmで大きさを0へ縮めて、現れ方と消え方を目立たなくする）。粒子は互いに4mm以上離れ、追い越さない。
- 粒子は、経路上の位置と拍動の位相で決まる速さで進み、閉じた弁の手前で止まる。後ろの粒子はその後ろに並ぶ。弁が開くと、並んだ粒子が通る。積分は最大4msずつで、弁が開閉する時刻（100・150・370・450・800ms）と心房の速さが変わる時刻をまたがないよう、そこで区切る（PR #30のレビューで、4msの真ん中の時刻で弁を判定すると、境界をまたぐ区間の全体に開弁中の移動量が入ると指摘され、直した。直す前は、148→152msを一度に進めた場合と150msで区切った場合で、粒子の位置が最大0.36mm違った）。
- 弁の開閉は`src/heartbeat.mjs`の`valvesAt`で決める。房室弁は心房の収縮中（0〜100ms）と、心室の弛緩のあとの充満（450〜800ms）に開き、動脈弁は駆出（150〜370ms）だけ開く。各時期の順序と長さはOpenStax 19.3による。
- **資料にない表示用の値**：等容性収縮50ms、等容性弛緩80ms（4つの弁がすべて閉じている時間）。1拍に心室の部分から出る割合（心室部分の列の60%）。心房の収縮が充満に占める割合の設定（25%。資料は「残り20〜30%」）。粒子の速さ（上の割合から、各経路の心室部分の長さと各期の長さで決めた。例：上大静脈の経路で、駆出0.17、受動的な充満0.081、心房の収縮0.095、静脈と動脈0.095 mm/ms）。粒子の数（経路の長さ÷6.5mmで、1本あたり36〜42、全部で235）。生理学的な速さではない。
- 拍動への追従：毎フレーム、拍動の変形（`createBeat`の`displace`）で粒子の位置を動かす。`THREE.InstancedMesh`は、`createBeat`が形状を変形しないよう補助物（`userData.helper`）にしてある。
- 経路を拍動の途中の状態で動かしても内側に残ることを、単体テストで検査する（心房の収縮の最大と半分、心室の収縮の最大と半分。経路を静止座標のままにすると、心房の収縮の最大で6本中1本、心室の収縮の最大で6本中2本、心室の収縮の半分でも2本が外れる）。粒子は、この経路の上を動く。

測定（Node、10拍。`tests/flow-particles.test.mjs`が検査する。弁の閉じている間は通らないことは、フレームの切れ目が小数の場合も検査する）：

- 閉じた弁の手前の壁（弁の面から2.1mm手前。下の「血流の模式弁尖」）を、弁の窓が閉じている間に通った粒子は0（房室弁は心房の収縮中と充満の間だけ、動脈弁は駆出の間だけ）。弁尖の面を、弁尖が完全に開いていないときに通った粒子も0。粒子の間隔は常に4mm以上。
- 10拍で、房室弁の弁尖の面を通った粒子534、動脈弁の弁尖の面を通った粒子535（全経路の合計）。経路ごとの差は3以内。（模式弁尖を入れた版で再測定。通過を数える位置が、弁の口の中心の近くの経路点から、弁尖の面との交点へ変わった。`bd65bd0`では548・548・心房の収縮中118、積分を弁の切替時刻で区切る前の`0de170a`では547・548・117だった）
- 房室弁を通った粒子のうち、心房の収縮中に通ったのは130（24.3%。`bd65bd0`では118、21.5%）。設定は25%だが、1拍に弁を通る粒子が経路あたり約9個のため、割合は約11%刻みになり、設定値どおりにはならない。資料の20〜30%の範囲に入る（検査の範囲は変えていない）。
- 1拍に動脈弁を通る粒子は、心室の部分に入る粒子の最大数（長さ÷間隔）の62.8%（設定は60%）。
- 拍ごとの再現：粒子の並びは毎拍ほぼ同じ場所に戻る。12拍で、前の拍の最も近い場所との距離は最大4.00mm（行列が1個ぶん違う）、増え続けることはなかった。
- 費用（Node、この環境のCPU）：粒子の更新は1フレームあたり0.005〜0.012ms、描画用の行列の計算は0.2ms。既存の拍動の変形は1.3〜1.4ms。GPUの負荷とiPhoneでの性能は未測定（ChromiumのSwiftShaderは、画面が拍動中に毎秒、外観11、刺激伝導系8.3、血流6.7フレーム。ソフトウェア描画で、実機の目安にならない）。粒子の数は`flowSettings.spacing`（6.5mm）を変えれば増減できる。

### 血流の模式弁尖（2026-11-08、案C）

Issue #28の基準「壁・弁・血管を突き抜けない」の、弁についての未達に対する対応。元データの弁尖は開閉の途中の1時点の形で、動かせない。通り道を探し直す案Aは、測定（Issue #28の2026-11-08の測定）で成立しなかった：静止形状で粒子が通れる最大の球の半径は、大動脈弁0.74mm、肺動脈弁0.73mm（半径1.5mmの粒子は通れない）、三尖弁1.52mm、僧帽弁1.68mm（壁を含めた場合。余裕が誤差以下）。2026-11-08のユーザー判断で、案C（血流表示用の模式弁尖）を採用した。**血流モードだけで描き、内部観察（断面）の弁は元の形のまま。**

形（`src/valves.mjs`）：

- 弁の口（`meta.flow.valves`の中心と半径）を中心とする円盤を、尖の数だけの扇形に分けた弁尖で表す。尖の数だけ、画面の部位説明（`src/anatomy.mjs`）に合わせた（三尖弁3、僧帽弁2、大動脈弁3、肺動脈弁3。この作業で資料の再確認はしていない。尖の向きや大きさの違いは表さない）。
- 各弁尖は、円弧の辺で輪に付いている。閉じると平らな円盤になり、開くと自由な角が軸から離れて下流へ立ち上がり、中央に丸い通り道ができる。弁尖の動きは、自由な角が直線で動く単純な補間で、実際の弁の動きではない。腱索と乳頭筋は表さない。
- 流れの軸は、その弁を通る経路の向きの平均。経路との傾きは最大2.0°（単体テストで25°未満を検査）。弁尖の最初の向き（どの方向に1枚目を置くか）は任意で、世界の上向きから決めた。

粒子との関係（`src/flow.mjs`。弁尖は描画だけでなく、粒子の動きの規則の一部）：

- 粒子は、弁の窓（`valvesAt`）が開いていて、かつ弁尖が完全に開いているときだけ、弁の手前の壁を越える。壁は、閉じた弁尖の面から2.1mm（粒子の半径1.5mm＋余裕0.5mm＋0.1mm）手前に、弁の軸に沿って置く。経路の傾きによる長さの違いも、経路と平面の交点から求めて合わせる。
- 弁尖は、窓が開く10ms前から開き始め、窓が終わると閉じ始める。ただし、(1)閉じるのは、弁の手前から弁の面へ向かっている粒子がいなくなってから、(2)次の姿勢が、弁の近くの粒子から2.0mm未満になる動き（1ステップの中間の姿勢も）は取らず、その位置で待つ、(3)**開き始めるのは、同じ側の相手の弁（三尖弁と肺動脈弁、僧帽弁と大動脈弁）が閉じてから**（開き具合0.05以下）。(3)がないと、閉じ遅れた房室弁と、先に開き始めた動脈弁が同時に全開になる（PR #32のレビュー。僧帽弁1・大動脈弁1が150msと160msで再現された）。
- 房室弁には、心室の列の上限も付けた：粒子は、心室の列（房室弁の手前の壁から動脈弁の手前の壁までの粒子）が動脈弁の手前に間隔4mmで詰まったとき、最後の粒子が弁の区間の外で止まる場合だけ、壁を越える。上限がないと、列が満杯のとき最後の粒子が弁の区間の中で止まり、駆出が列を動かすまで弁尖が閉じられなかった（僧帽弁は窓が終わってから86〜88ms後、三尖弁は24ms。ramp 25msの時点）。上限を入れても1拍に通る粒子はほとんど変わらなかった。原因が「最後の粒子が弁の区間の中で止まること」だという確認は、対策の効果（遅れが24〜38msに縮んだ）による。
- 弁の区間（壁から、弁の面の先の約4.1〜4.6mm［弁尖の高さ＋2mm］まで）では、粒子は駆出の速さ以上で進む。弁の口で血液が速くなる様子を、表示用に取り入れた。これがないと、弁尖が閉じるのを粒子の列が長く止めた。

### 刺激の伝わりと模式心電図（2026-11-14、段階B）

「拍動を再生」で、刺激伝導系の画面（と、断面で「刺激伝導系を重ねる」を押したとき）に、拍動の時計と同じ位置で刺激の伝わりが動く。光る白い点が先頭で、通った部位はしばらく明るく残る（120msで1/eに減る表示用の減衰）。画面左上の時期の欄に、今の区間の名前を出す。停止中は、拍動の途中で止めればその時刻の状態を表示し、静止時（位置0）では今までと同じ見た目に戻る。刺激伝導系の画面には模式の心電図（SVG）も出て、直近1秒ぶんの波が右へ流れる。スマホ幅では、ページ内のスクロール欄（モード切替の下）に置く。

**経緯**：段階Bは、README「現在の版と範囲」の「伝導時間は再現しない」という設計判断の変更だったため、2026-11-14に案を3件示してユーザーが選んだ（案1：順序と前後だけ表示用の時刻で／案2：資料の値に合わせる／案3：時間をつながず位相に連動）。AIの推奨は案1。**ユーザーは案2を選んだ**。案を示したときのAIの説明には誤りがあった。案2を「経路長で配分する」と書き、「資料に区間ごとの時間はない」と受け取れる言い方をしたが、OpenStax 19.2の本文には区間ごとの所要時間がある（下）。そのため実装は経路長による配分をせず、資料の区間時間をそのまま使った。この訂正は選択の後にわかった。

**資料と取得経路**：[OpenStax Anatomy and Physiology 2e 19.2](https://openstax.org/books/anatomy-and-physiology-2e/pages/19-2-cardiac-muscle-and-electrical-activity)（登録不要、CC BY-NC-SA。文章や図は取り込まない）のHTMLを、2026-11-14にAIが直接取得し、本文のテキストを取り出して読んだ（別のモデルによる要約は介していない。人による原文確認ではない）。本文の値：洞房結節から房室結節まで約50ms、房室結節を通る間が約100ms、房室束と脚が心尖へ届くまで約25ms、プルキンエ線維で心室筋の全体に届くまで約75ms。心房はP波の始まりの約25ms後に収縮を始め、心室はQRSがR波の頂点に達するときに収縮を始める。心筋の活動電位は250〜300msで、再分極は約75ms。**図（図19.20の心電図など）は見ていない**。P波・QRS・T波の長さは本文にない。

**資料の中の食い違い**：同じ本文に「洞房結節から心室の脱分極までの合計は約225ms」ともあるが、4つの区間を足すと250msになり、本文の中で合っていない。この表示は4つの区間の値を使った。

**拍動の時計への置き方（表示用の位置合わせ）**：拍動の時計（`heartbeat.mjs`、OpenStax 19.3）は心房の収縮から始まり、心室の収縮が100msに始まる。本文は、刺激が心室の筋へ広がってから（手順5）心室が収縮する（手順6）順なので、心室の収縮の始まり（100ms）を、プルキンエ区間の始まりに置いた。そこから逆算して、脚が75〜100ms、房室結節が−25〜75ms、心房への広がりが−75〜−25msになる。洞房結節は拍の始まりの75ms前（前の拍の終わり）に発火し、心房の収縮は、刺激が房室結節に届いた25ms後に始まる。**本文の「P波の始まりの約25ms後」とは50ms違う**。25msに合わせると、刺激が届く前に心室が収縮してしまうため、順序を優先した。T波は、心室の収縮の終わり（370ms）で終わる75msの区間に置いた（活動電位の長さが本文の250〜300msの範囲に入るのは、270msだから）。時刻は`src/conduction-timing.mjs`が`cycle`から計算する。

**画面での決め方**：
- 心房への広がり（破線2本）は、同じ50msで先頭が進む。洞房結節はこの区間で光る。
- 房室結節は、約100msの間、明るく残る（足止めの表示）。
- ヒス束の2区間と左右の脚の25msは、経路の長さに比例して、ヒス束→（分岐区間）→左右の脚の順に配分し、脚は並行して終点に同時に届く。左脚の面（シート）は点を持たず、区間の間だけ明るくなる。
- プルキンエ線維（4本）は、各線の始点から終点まで75msで進む。
- 心電図：P波は心房の区間、QRSは脚とプルキンエの区間でR波の頂点が100ms、T波は再分極の区間にある。**波の高さと幅は表示用**で、目盛りは出さない（電圧や時間の単位を読めない）。

**確認したこと**：

- `tests/viewer.spec.js`（ブラウザー）：偽の時計で、20・80・105・125・340・740msに止めたとき、時期の欄の文が区間と合うこと、心電図の最後の点が式の値と0.2以内で一致すること、頭部の白い画素（プルキンエ区間で出る。105msで102、125msで24。頭部が出ない20msと340msは0）。頭部を非表示にする変更は、このテストが失敗する。断面の重ね表示で拍動中にエラーが出ないこと、心電図が刺激伝導系の画面だけにあること。

### 血流モードの経路強調（2026-11-14、段階B）

血流の画面で部位を選ぶと、その部位を通る経路の粒子を少し大きく、他の経路の粒子を小さく暗くする（色を0.3倍、大きさを0.55倍。強調側は1.2倍）。画面の注に、強調した経路の名前を書く。

- 対応は`src/flow.mjs`の`routeParts`：右心系の経路（上大静脈・下大静脈）は、大静脈・右心房・右心室・肺動脈を通り、左心系の経路（4本の肺静脈）は、肺静脈・左心房・左心室・大動脈を通る。この対応は、経路の検査（`tests/flow.test.mjs`）が使う心腔と血管の組と一致することを単体テストで検査する。冠動脈・冠静脈はどの経路にも含まれず、選ぶと何も暗くしない。
- 部位は種類ごとに1つで、経路は右の2本と左の4本の2通りにしか分かれない。そのため、同じ側の部位を選ぶと同じ経路が強調され、「上大静脈だけ」のような絞り込みはできない。
- 画面に入った直後の初期選択（左心室）では強調しない。ユーザーがボタンかモデルで選んだときだけ。血流以外の画面（断面の血流の重ね表示を含む）では強調しない。
- 既存のブラウザーテスト（血流画面の粒子の画素数）は、強調によって右心室を選ぶと左心系の赤が暗くなるため、選ぶ部位を「右心室」から「冠動脈」に変えた。画素数の閾値は変えていない（冠動脈は粒子の見た目を変えない）。
- 確認：単体テスト2件（部位と経路の対応、粒子の経路番号）、ブラウザーテスト1件（右心房・左心室・冠動脈で、赤と青の画素数が変わること、モードを離れると注が消え、戻ると強調なしから始まること。強調を無効にする変更はこのテストが失敗する）、1280×800の画面の目視（右心房を選んだとき、青い粒子が目立ち、赤い粒子が小さく暗い）。スマホ幅での見え方は撮っていない（未確認）。

2026-11-07にURLから取得し直したzipのハッシュは記録と一致し、そのzipから作り直したデータは保存済みのものとバイト単位で同一だった。

ユーザーにビルドを要求しない。

## 設計判断

- 外部CDN、外部モデル、外部フォントに実行時依存しない。
- 部位は安定したIDで管理し、画面と3D選択を同期する。
- 外観形状と刺激伝導系を別レイヤーにし、透過した外形が内部選択を遮らないようにする。
- スマートフォン幅（760px以下）では、ページ全体はスクロールさせない。見出し、モデル、選択中の部位の説明を上部に固定し、部位ボタンと操作欄はその下の専用の欄の中だけでスクロールする。説明欄は高さを固定し、部位を選んでも下のボタンがずれないようにする。2026-11-07のユーザーの実機確認で、v0.4.1の最初の版（ページをスクロールし、モデルと説明を`position: sticky`で止める方式）では、部位ボタンや操作欄がモデルの下にもぐり込んでいくと分かったため変更した。
  モデルと説明欄は、スクロールする欄の中にも`position: fixed`の要素の中にも置かない。スマートフォン幅のときだけ、`main.js`がこの2つを`main`の前の欄（`#pinned`）へ移し、画面を「見出し／モデル／説明／スクロール欄」の縦並びにする。PC幅では元の位置へ戻す。`position: fixed`のモデルをスクロールする欄の中に置いた版（`7535baf`）で、モデルの部分が最初から真っ暗だったため変えた。ただしこの結果は、iPhoneのファイルAppから他社のHTML表示アプリ「HTML Keep」で開いたもので、Safariではない（[docs/validation/verification-history.md](docs/validation/verification-history.md)の「これまでの実装と実機の確認記録」）。その後、iPhoneのSafariでも`7535baf`はモデルが真っ暗で、この方式（`66299c8`）では映ることを確かめた（下の「検証状況」）。
- 静止時は必要なときだけ描画する。自動回転は初期停止で、ユーザー操作やタブ非表示時にも停止する。
- 画面比率とモデル全体の境界から初期距離を計算し、視点切り替えとリサイズでも適用する。
- 外観はBodyParts3Dの形状に一本化する（2026-11-07）。手作りの概形は精度不足のため廃止した。
- 刺激伝導系は外観と同じ座標系に置き、透過した外観の中に表示する。
- 内部は断面で見せる（2026-11-07）。半透明の壁は部屋の区別がつかず、内腔の鋳型は弁を隠すため採らない。
- 全体を見渡す用の半透明の壁（案B）は足さない（2026-11-07、ユーザー判断）。
- 外部データは変換済みの軽量メッシュだけをリポジトリに置き、ビルド時はネット接続を使わない。
- iPhoneでふだん使う配布方法は、claude.aiの非公開ページとする（2026-11-07、ユーザー判断）。GitHub Pagesは使わない（公開設定の変更になるため）。iPhoneのSafariは端末に保存したHTMLを開けない。index.htmlを更新したら、同じバイトのまま非公開ページを置き直す。
- 拍動と血流は1本の時間軸（心房の収縮→心室の収縮→心室の弛緩）で同期させ、拍動を先に作る。血流は外形を透過させて粒子で見せる。拍動の速さは、初期はゆっくり（5倍）で、実際の速さに切り替えられる（2026-11-08、ユーザー判断）。
- 拍動と血流の自動再生は追加しない。初期停止を維持し、再生ボタンから開始する（2026-11-08、ユーザー承認）。
- 血流は、外形を透かす（2026-11-14以降は不透明度0.07＋縁の明るさ。段階3の時点は0.12）「血流」モードを別に設け、他のモードの見た目と描画を変えない（2026-11-08、段階3）。粒子は拍動の時間軸（`valvesAt`）で動かし、閉じた弁の手前で待たせる。粒子の速さ・数・等容性の長さは表示用の値。
- 血流の経路は、生成スクリプトで内腔・弁・血管から計算し、静止時の座標でデータに入れる。拍動への追従は、表示側が毎フレーム`displace`で行う（2026-11-08、段階2）。経路の検査に使う内腔は、画面には出さない部品としてデータに入れ、生成時と単体テストで同じ判定を使う。
- 血流モードの弁は、元データの弁尖ではなく、血流表示用の模式の弁尖（2026-11-08、ユーザー判断で案C。案Aは測定で成立せず）。内部観察の弁は元の形のまま。弁尖は粒子の動きの規則の一部で、粒子が触れないことを単体テストで検査する（「血流の模式弁尖」）。
- 拍動の変形は、頂点シェーダーではなくCPUで頂点を動かす。クリック判定とラベルの遮蔽判定がCPU側の形状を使うため、描いた形と判定を一致させるため（変形する頂点は約3.3万個で、毎フレームの計算は軽い）。
- 趣味の範囲のため、拍動の見た目が自然かどうかの確認と、解剖学の資料との照合を、今後の作業項目から外す（2026-11-08、ユーザー判断）。対象は、拍動の縮み方、血流の経路・弁の口・模式弁尖の位置と形、刺激伝導系の位置の定量照合。**照合していない事実と「医療用ではない」の表記は変えない**：各節の「未照合」「未確認」の記述はそのまま残し、確認済みとは書かない。照合の予定がなくなっただけで、模式であること（簡略化・推定・表示用の値）は画面とREADMEに書き続ける。刺激伝導系の調査や配置変更に着手する場合は、AGENTS.mdのとおり先に照合資料を読む。
- 刺激の伝わりと模式心電図は、拍動の時計に載せ、4つの区間の時間はOpenStax 19.2の本文に合わせる（2026-11-14、段階B。AIは「順序と前後だけ表示用の時刻で」の案1を推奨し、ユーザーが「資料の値に合わせる」の案2を選んだ）。これは「伝導時間は再現しない」からの変更で、位置の照合を作業対象外にした2026-11-08の判断は変えない。区間の中の進み方と心電図の波の形は表示用。
