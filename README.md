# 心臓のアトリエ

個人の趣味として、人間の心臓を回して眺め、構造を楽しむ3Dモデルを作るプロジェクト。
最終成果物は単一のHTML。
設計、実装、検証はChatGPTとClaudeが交代して担当する。

## 開き方

`index.html`をダウンロードしてWebGL対応ブラウザーで開く。
コードとライブラリは内蔵しており、モデル表示にネット接続は不要。
参考リンクを開く場合だけネット接続が必要。
iPhoneのSafariは、端末に保存したHTMLを開けない。2026-11-07に、claude.aiの非公開ページに置いたものをiPhoneのSafariで開き、表示を確認した（「検証状況」）。iOSのファイルプレビューや他社のHTML表示アプリでの動作は未確認・対象外（Issue #9）。
プレビューアプリではなくブラウザーでの表示を対象とする。

- ドラッグ／タッチで回転、スクロール／ピンチで拡大縮小。
- 部位ボタンまたはモデルのクリックで部位を選択。
- 「外観」「刺激伝導系」を切り替えて観察。
- 刺激伝導系では「前へ」「次へ」で電気刺激の経路を順に確認。
- 前面、背面、身体の左側へボタンで移動。
- モデルにキーボードフォーカスを移すと、矢印キーで回転、＋／−で拡大縮小、Homeで前面へ戻る。

## 現在の版と範囲

v0.4は、BodyParts3Dの成人男性1体の心臓と周囲の血管を外観とし、刺激伝導系の模式表示と、断面による内部表示を加えた試作。
2026-11-07のユーザー判断で、v0.2までの手作りの概形（球と管）を廃止し、BodyParts3Dの形状に置き換えた。

外観では心房、心室、大動脈、肺動脈、大静脈、肺静脈、冠動脈、冠静脈を選択できる。
心房・心室の境界は自動推定で、実際の境界とは一致しない。
形状は1体分のデータで、個人差や拍動による変化は表さない。

刺激伝導系は洞房結節、心房への広がり、房室結節、ヒス束、右脚、左脚、プルキンエ線維を説明する独自形状。右脚と左脚は別々に選べ、色も分けた（どちらも1本の線に簡略化。左脚は実際には幅の広い板状で3つの束に分かれる）。
BodyParts3Dに刺激伝導系の形状はないため、周囲の構造から位置を推定した（「刺激伝導系の配置」参照）。
心房への広がりは破線で表し、独立した神経や血管と混同しないようにする。
太さは説明用に誇張しており、伝導時間は再現しない。

内部（断面）では、前後方向の平面で心臓を切り、内腔の面、壁の切り口、弁、乳頭筋を見せる（2026-11-07、ユーザー判断で案Aを採用。「内部観察の表示方式の比較」参照）。
断面の位置はスライダーで前後に動かせる。断面は心臓に固定し、回転すると切り口を斜めから見られる。
選択できるのは心房・心室、僧帽弁、三尖弁、大動脈弁、肺動脈弁、乳頭筋。
「刺激伝導系を重ねる」を押すと、刺激伝導系も同じ断面で切って重ね、選べるようになる（初期状態はオフ）。
切り口の面は心臓の壁にだけ作る。血管は元データに壁の厚みがない薄い殻なので、切ると内腔が見え、切り口の面は作らない（冠動脈・冠静脈・肺静脈は閉じた形だが、同じ扱いにしている）。
弁と乳頭筋はBodyParts3D 4.0の形状で、弁の開き具合は元データの1時点のもの。
元データの乳頭筋は右心室の3つと左心室の外側乳頭筋（前外側の頭を含む）だけで、左心室の後ろの乳頭筋はない（OpenStax 19.1では左心室に前と後ろの2つ）。画面の説明にもそう書いた。
血流と拍動は未実装。
医療用途ではない。

## 進め方

1. 外観試作：回転と拡大縮小、主要部位の選択。
2. 最初の完成版：資料との形状照合、外観の改善、部位説明と操作の調整。
3. 内部観察：内腔と弁を表せるモデル構造を検討してから実装。v0.4で断面表示を実装した。
4. 動き：血流方向と説明用の拍動を追加。

まずPCで確認し、スマートフォンでも操作しやすくする。
見栄えの良さと、主要部位の位置とつながりを説明できることを目標にする。
刺激伝導系の模式表示はユーザー指定の参考資料を受けて追加したが、内部構造の完成を意味しない。

## 参考資料と外部素材の採用方針

参考文献、参考サイト、参考3Dモデルは、無料かつ会員登録・ログイン不要で必要な内容を閲覧できるものに限定する。
外部素材を取り込む場合は、データの取得も同じ条件を満たすものに限る。
有料素材、登録・ログイン必須の資料、無料体験への登録が必要な資料は採用しない。
ユーザーが明示的に方針変更するまで、この条件を維持する。

無料閲覧は、モデルや画像の複製・改変・再配布の許可を意味しない。
参考に読む場合と、HTMLやリポジトリに素材を取り込む場合を区別し、後者ではライセンスと出典を確認する。

### 刺激伝導系の検証範囲（現在、2026-11-08、main `827489b`を確認）

AIが交代したときの重複調査と完了判断の誤りを防ぐため、現在の範囲をここ1か所にまとめる。詳細な数値は「検証状況」の各項目にある。過去の記録には対象の版を付けている。

- 位置が解剖学的に妥当かは、**確認していない**。房室結節とヒス束は、資料の文章が述べる局所解剖（コッホの三角の頂点、無冠尖・右冠尖の下の中隔の頂）に合わせて置き直した（2026-11-07、ユーザー判断）。資料の図や断面画像との描画比較はしていない。
- 局所解剖との対応（下の表）。資料はStephensonら（2017）とChenら（2025）の本文。コッホの三角の境界はWikipedia「Koch's triangle」による（三次資料。原典は有料で未確認）。

### ヒス束の向きの再点検（2026-11-08）

対象はmain `827489b`。生成コードの座標変換と生成データを確認し、Chenら（2025）の§3.1、§3.5と[図6の画像](https://www.frontiersin.org/files/Articles/1507005/xml-images/fmed-12-1507005-g006.webp)を閲覧した。
図6Aが非心筋梗塞標本0059、BとCが心筋梗塞標本で、図中には前面からの冠状面表示と記載されている。
画像は取り込んでいない。

- 生成コードは元座標 `(x, y, z)` を表示座標 `(x, z + 補正, -y)` に変換する。表示座標の+Xは身体の左、+Yは上、+Zは前。表示データのヒス束4点の両端差は `(18.2, -4.5, -2.0) mm` で、READMEの既存計測と一致した。軸の読み違いでは、この前後差を説明できない。
- 隣り合う4点を順に結んだ折れ線長は20.686mm（両端の直線距離ではない）。これは生成データの折れ線長で、画面のCatmull–Rom曲線の長さでも、組織学的なヒス束の測定値でもない。
- §3.1は房室伝導軸が後上方から前下方へ進むと記載し、§3.5は貫通束が膜性中隔の下縁に沿って前方へ進むと記載する。モデルの房室結節から分岐点までの全区間と、論文の貫通束という部分区間は対応づけが未了。心臓の傾きと区間の定義をそろえずに、前後の符号だけで誤配置を確定したり、経路を反転したりしない。
- §3.5では0059の左右脚が後乳頭筋へ向かう傾向、心筋梗塞標本の右脚が前乳頭筋へ向かう傾向を記述する。モデルの右脚は前乳頭筋を終点に使う。図6AとB/Cを混ぜて適合を判断せず、Stephensonの図4と別標本の資料で、中隔縁柱と右脚の途中経路も照合する。1標本の傾向を正常例全体の規則とはしない。

現行モデルの弁と伝導系だけを描く確認を試みたが、この作業環境のChromiumは起動時にソケットの権限エラーで終了し、描画できなかった。
今回確認したのは論文の画像と、コードおよび生成データの数値であり、現行モデルの見え方や解剖学的な妥当性は未確認。
Kawashima・Sato（2021）の出版社本文も取得できなかった。
追記：対応表の「前後・上下の向きは資料の文章と逆」という判定を訂正した。Chen §3.1は前下方への進行を記述しており、モデルの下向きまで逆とするのは誤りだった。上下の記述が異なる資料を一括せず、部位と対象区間ごとに比較する。
次の作業は、図6Aと対応する部位を現行モデルで描き、房室結節、貫通部、分岐部の対応を分けて確認すること。Issue #17の資料照合は未完了のままとする。

- 大きさは長さ約12cm、幅約8cm、厚さ約6cm。
- 大血管がつながる上面が心底、下端が心尖。心尖は胸骨のやや左に向く。

### BodyParts3D試作の作り方（2026-11-07）

4.0の心臓には心室の心筋（壁）のメッシュがなく、心室は内腔、弁、乳頭筋だけだった。

壁を約2.7万面へ減らし、各三角形を最も近い4.0の心腔（左右の心房・心室）に割り当てて区分けした。
前面では、右心室と左心室の推定境界が前室間枝（冠動脈）の走る位置とほぼ一致することを画面で確認した。

各部位の出どころ（IDは`scripts/prepare-bodyparts3d.mjs`の`parts`）：

- 3.0：心臓の壁（FMA7274）、大動脈の本体3部品（FMA3736、FMA3768、FMA3784）、大静脈（FMA4720、FMA10951）。3.0のファイルには名称の記載がなく、大動脈・大静脈との対応は既存の記述に従っており、名称の照合は未了。

### 内部観察の表示方式の比較（2026-11-07）

断面（案A）を推奨し、2026-11-07にユーザーが採用した。

元データを調べた結果は次のとおり。

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A 断面 | 平面で壁と血管を切り、切り口と内面、4.0の弁・乳頭筋を見せる | 4つの部屋と中隔の位置関係、左心室の壁が厚いことが見て分かる。壁の内面がそのまま内腔になる | 切り口の塗りつぶしが必要。切った側をクリックで選べないようにする処理が要る |

案Cは画面を撮っていない。弁が心腔の内側にあることを数値で確認しただけ。

案Aの実装（v0.4）：

- 断面は心臓に固定した前後方向の平面1枚。位置はスライダーで動かす。四腔断面などの標準断面には、今は合わせない（2026-11-07、ユーザー判断。下の照合を見てから再検討する）。
- 弁尖11個を4つの弁、乳頭筋5個を1つの部位にまとめて生成データに追加した。僧帽弁と三尖弁は面数を30%、ほかは50%に減らした。生成データは約460KBから約590KBになった。既存の部位と刺激伝導系の座標は変わらない。
- 切り口は、心臓の壁にだけ、切断平面の上に実際の面（大きな四角形）を置いて表す（v0.4.1で変更。v0.4は断面越しに見える元の形の裏面を単色で塗っていたため、塗りの奥行きが切断平面と一致せず、血管の管の内側も切り口と同じ色になった）。
  壁の面のうち平面より奥にあるものを、画素ごとに数える（裏面は＋1、表面は−1。ステンシル法）。数が0でない画素にだけ面を描く。壁の外面と内面の間は0でなく、内腔は0になるので、内腔は切り口の色にならない。
  壁の4つの心腔は合わせて閉じた面になっていることを単体テストで確認した（辺の使用回数がすべて偶数）。
  血管（大動脈・肺動脈・大静脈）は壁の厚みがない薄い殻で、切り口に両端が開いている。面を作ると内腔まで塗ってしまうので作らず、両面を描いて内腔を見せる。
- 内部モードでは、各部位を断面で切った複製に差し替える（壁は表側だけ、血管などは両面）。切り口の面は平面上にあり、ほかの面と同じ奥行きで重ならない。モードの切り替えは表示・非表示の入れ替えだけで、マテリアルを変えない。
- Three.jsのクリック判定は断面も表示・非表示も考慮しないため、表示されていない面と断面より手前の交点を除く（`pickPart`）。
- 描かれた切り口もクリックで選べる（v0.4.1）。平面上の点から奥へ光線を延ばして壁の面を数え、0でなければ切り口が描かれているので、その先で最初に当たる壁の面の心腔を返す。v0.4は切り口を判定に含めず、左心室の切り口をクリックしても奥の僧帽弁などが選ばれた（数値で再現）。切り口は視点が切断面より手前（取り除いた側）にあるときだけ判定する。
- 刺激伝導系は断面と重ねて見せる（2026-11-07、ユーザー判断）。3案を比べた。
  - 常に重ねる案：弁と腱索の観察を妨げ、部位ボタンが15個になるため採らない。
  - 切らずに重ねる案：取り除いた手前側に経路が浮き、位置を誤認させるため採らない。
  - 採用：切り替えボタンを付け、オンのときだけ同じ断面で切って重ね、選べるようにする。初期状態はオフ。オンのときは刺激伝導系の注記（位置は推定）も出す。
- 刺激伝導系の素材には、切断面を1枚、どのモードでも付けておく。刺激伝導系モードでは、その面を何も切らない位置へ逃がし、内部モードでは断面と同じ位置に置く。切り替えで切断面の数が変わらないので、描画処理（シェーダー）を作り直さずに済む設計にした（作り直しの有無は計測していない）。
- 断面で取り除いた側にある部位のラベルは出さない。
- 重ねても、見えるのは内腔の表面に出ている部分だけ（洞房結節、心房への広がり、房室結節、脚の一部など）。経路の多くは不透明な壁の陰になる（画面で確認）。
- 刺激伝導系の各部位が全部切り取られるスライダー位置（太さを含む形状の範囲から計算、2026-11-07の置き直し後）：右脚0.01、房室結節0.02、左脚0.02、ヒス束0.08、心房への広がり0.65、プルキンエ線維0.68、洞房結節0.71。0.72より後ろでは全部が切り取られる。置き直し前（`3101bfe`まで）は房室結節0.26、ヒス束0.28、左右の脚0.25〜0.26で、0より後ろでも房室結節とヒス束が残っていた。

## AI向け開発手順

`npm ci` → `npm run build` → `npm run test:unit` → `npm test`。
テスト用Chromiumがなければ `npx playwright install chromium`。
BodyParts3Dデータを作り直す場合だけ、[3.0のzip](https://dbarchive.biosciencedbc.jp/data/bodyparts3d/20110915/BodyParts3D_3.0_obj_99.zip)と[4.0の部位別zip](https://dbarchive.biosciencedbc.jp/data/bodyparts3d/LATEST/partof_BP3D_4.0_obj_99.zip)を取得し、`node scripts/prepare-bodyparts3d.mjs <3.0のzip> <4.0のzip>`を実行する。
zipはリポジトリに入れない。
スクリプトは入力zipのSHA-256を検査し、記録（3.0は`2125f6d7…`、4.0は`9fbc713f…`。全桁はスクリプト内）と違えば止まる。4.0の取得先がLATESTのURLで、将来別のデータに差し替わっても気づけるようにするため。意図的に別の入力を試すときだけ`ALLOW_UNVERIFIED_INPUT=1`を付ける（その出力はコミットしない）。
2026-11-07にURLから取得し直したzipのハッシュは記録と一致し、そのzipから作り直したデータは保存済みのものとバイト単位で同一だった。
システムのChromiumを利用する場合は `CHROMIUM_PATH=/path/to/chromium npm test`。
ユーザーにビルドを要求しない。
ソースと生成物を同じコミットに含める。

| ファイル | 役割 |
|---|---|
| `src/main.js` | 描画、選択、モード切り替え、操作 |
| `src/conduction.mjs` | 刺激伝導系の模式表示（座標は生成データから読む） |
| `src/anatomy.mjs` | BodyParts3Dデータの読み込みと外観の部位定義 |
| `src/data/bodyparts3d-heart.bin` | BodyParts3Dから生成した軽量メッシュ |
| `scripts/prepare-bodyparts3d.mjs` | BodyParts3Dのzipから上記メッシュと刺激伝導系の座標を生成 |
| `src/viewer-state.mjs` | 画角、断面（切り口の面）、クリック判定、タップ判定 |
| `src/template.html` | 日本語画面 |
| `scripts/build.mjs` | Three.jsと権利表記を単一HTMLへ埋め込む |
| `index.html` | 配布用生成物 |

## 設計判断

- 外部CDN、外部モデル、外部フォントに実行時依存しない。
- 部位は安定したIDで管理し、画面と3D選択を同期する。
- 外観形状と刺激伝導系を別レイヤーにし、透過した外形が内部選択を遮らないようにする。
- スマートフォン幅（760px以下）では、ページ全体はスクロールさせない。見出し、モデル、選択中の部位の説明を上部に固定し、部位ボタンと操作欄はその下の専用の欄の中だけでスクロールする。説明欄は高さを固定し、部位を選んでも下のボタンがずれないようにする。2026-11-07のユーザーの実機確認で、v0.4.1の最初の版（ページをスクロールし、モデルと説明を`position: sticky`で止める方式）では、部位ボタンや操作欄がモデルの下にもぐり込んでいくと分かったため変更した。
  モデルと説明欄は、スクロールする欄の中にも`position: fixed`の要素の中にも置かない。スマートフォン幅のときだけ、`main.js`がこの2つを`main`の前の欄（`#pinned`）へ移し、画面を「見出し／モデル／説明／スクロール欄」の縦並びにする。PC幅では元の位置へ戻す。`position: fixed`のモデルをスクロールする欄の中に置いた版（`7535baf`）で、モデルの部分が最初から真っ暗だったため変えた。ただしこの結果は、iPhoneのファイルAppから他社のHTML表示アプリ「HTML Keep」で開いたもので、Safariではない（下の「検証状況」）。その後、iPhoneのSafariでも`7535baf`はモデルが真っ暗で、この方式（`66299c8`）では映ることを確かめた（下の「検証状況」）。
- 静止時は必要なときだけ描画する。自動回転は初期停止で、ユーザー操作やタブ非表示時にも停止する。
- 画面比率とモデル全体の境界から初期距離を計算し、視点切り替えとリサイズでも適用する。
- 外観はBodyParts3Dの形状に一本化する（2026-11-07）。手作りの概形は精度不足のため廃止した。
- 刺激伝導系は外観と同じ座標系に置き、透過した外観の中に表示する。
- 内部は断面で見せる（2026-11-07）。半透明の壁は部屋の区別がつかず、内腔の鋳型は弁を隠すため採らない。
- 全体を見渡す用の半透明の壁（案B）は足さない（2026-11-07、ユーザー判断）。
- 外部データは変換済みの軽量メッシュだけをリポジトリに置き、ビルド時はネット接続を使わない。
- iPhoneでふだん使う配布方法は、claude.aiの非公開ページとする（2026-11-07、ユーザー判断）。GitHub Pagesは使わない（公開設定の変更になるため）。iPhoneのSafariは端末に保存したHTMLを開けない。index.htmlを更新したら、同じバイトのまま非公開ページを置き直す。
- 専用の引き継ぎ書やSTATUS.mdは設けない。判断はREADME、変更理由と検証はコミット、未完了事項はIssueに残す。
