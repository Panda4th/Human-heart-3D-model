# 心臓のアトリエ

個人の趣味として、人間の心臓を回して眺め、構造を楽しむ3Dモデルを作るプロジェクト。
最終成果物は単一のHTML。
設計、実装、検証はChatGPTとClaudeが交代して担当する。

## 開き方

`index.html`をダウンロードしてWebGL対応ブラウザーで開く。
コードとライブラリは内蔵しており、モデル表示にネット接続は不要。
参考リンクを開く場合だけネット接続が必要。
iOSのファイルプレビュー、実機Safariでの動作は未確認。
プレビューアプリではなくブラウザーでの表示を対象とする。

- ドラッグ／タッチで回転、スクロール／ピンチで拡大縮小。
- 部位ボタンまたはモデルのクリックで部位を選択。
- 「外観」と「刺激伝導系」を切り替えて観察。
- 刺激伝導系では「前へ」「次へ」で電気刺激の経路を順に確認。
- 前面、背面、身体の左側へボタンで移動。
- モデルにキーボードフォーカスを移すと、矢印キーで回転、＋／−で拡大縮小、Homeで前面へ戻る。

## 現在の版と範囲

v0.2は外観の概形と刺激伝導系の模式表示を備える試作。
心房、心室、主要血管をコードで生成する。
刺激伝導系は洞房結節、心房への広がり、房室結節、ヒス束、右脚・左脚、プルキンエ線維を説明する独自形状。
心房への広がりは破線で表し、独立した神経や血管と混同しないようにする。

形状、重なり、血管接続、比率の解剖学的精度は未検証。
中空の心腔を持たず、透過表示は実際の断面ではない。
刺激伝導系の位置と太さは説明用に模式化しており、伝導時間は再現しない。
内腔、弁、冠動脈、血流、拍動は未実装。
医療用途ではない。

## 進め方

1. 外観試作：回転と拡大縮小、主要部位の選択。
2. 最初の完成版：資料との形状照合、外観の改善、部位説明と操作の調整。
3. 内部観察：内腔と弁を表せるモデル構造を検討してから実装。
4. 動き：血流方向と説明用の拍動を追加。

まずPCで確認し、スマートフォンでも操作しやすくする。
見栄えの良さと、主要部位の位置とつながりを説明できることを目標にする。
刺激伝導系の模式表示はユーザー指定の参考資料を受けて追加したが、内部構造の完成を意味しない。

## 参考資料と外部素材の採用方針

参考文献、参考サイト、参考3Dモデルは、無料かつ会員登録・ログイン不要で必要な内容を閲覧できるものに限定する。
外部素材を取り込む場合は、データの取得も同じ条件を満たすものに限る。
有料素材、登録・ログイン必須の資料、無料体験への登録が必要な資料は採用しない。
ユーザーが明示的に方針変更するまで、この条件を維持する。

無料閲覧は、モデルや画像の複製・改変・再配布の許可を意味しない。
参考に読む場合と、HTMLやリポジトリに素材を取り込む場合を区別し、後者ではライセンスと出典を確認する。

### MSD / BioDigital

ユーザー指定の[MSD「心臓の刺激伝導系」](https://www.msdmanuals.com/ja-jp/home/multimedia/3dmodel/心臓の刺激伝導系)を構造説明の参考とする。
画面から元ページを別タブで開ける。
同ページの3D表示はBioDigital製で、2026-11-07のこちらのクラウドブラウザーではWebGL初期化エラーとなり、3D画面の視覚比較は未完了。

モデルファイル、画像、テクスチャ、MSD向け埋め込みキーは取り込んでいない。
[BioDigital利用条件](https://www.biodigital.com/terms)ではアプリ外のコンテンツ配布に制限があり、[埋め込み機能](https://support.biodigital.com/hc/en-us/articles/360043705853-3D-embed-publishing-settings)も契約プランに依存する。
今回の単一HTMLにデータを複製できる許諾は確認できていないため、参考リンクと独自実装で反映する。

BodyParts3Dのライセンスは、公式の利用許諾ページの記載（CC BY 4.0）と、2013年のデータ内注記（CC BY-SA 2.1 日本）が食い違う。
取り込む場合は公式ページの記載と確認日をREADMEと権利表記に残し、データ内注記との差も明記する。
法的な解釈は未確認で、必要なら提供元へ問い合わせる。

OpenStaxから照合に使う主な点：

- 大きさは長さ約12cm、幅約8cm、厚さ約6cm。
- 大血管がつながる上面が心底、下端が心尖。心尖は胸骨のやや左に向く。
- 右側は前方へ、左側は後方へ寄る。
- 心房と心室の間に冠状溝、心室の間に前・後室間溝があり、冠動脈が走る。
- 左心室の壁は右心室より厚い。

## AI向け開発手順

`npm ci` → `npm run build` → `npm run test:unit` → `npm test`。
テスト用Chromiumがなければ `npx playwright install chromium`。
システムのChromiumを利用する場合は `CHROMIUM_PATH=/path/to/chromium npm test`。
ユーザーにビルドを要求しない。
ソースと生成物を同じコミットに含める。

| ファイル | 役割 |
|---|---|
| `src/main.js` | 描画、選択、モード切り替え、操作 |
| `src/model.mjs` | 独自の外観概形 |
| `src/conduction.mjs` | 独自の刺激伝導系模式表示 |
| `src/viewer-state.mjs` | 画角とタップ判定 |
| `src/template.html` | 日本語画面 |
| `scripts/build.mjs` | Three.jsと権利表記を単一HTMLへ埋め込む |
| `index.html` | 配布用生成物 |

## 設計判断

- 外部CDN、外部モデル、外部フォントに実行時依存しない。
- 部位は安定したIDで管理し、画面と3D選択を同期する。
- 外観形状と刺激伝導系を別レイヤーにし、透過した外形が内部選択を遮らないようにする。
- 静止時は必要なときだけ描画する。自動回転は初期停止で、ユーザー操作やタブ非表示時にも停止する。
- 画面比率とモデル全体の境界から初期距離を計算し、視点切り替えとリサイズでも適用する。
- 外観試作の形状を将来の内部モデルとして使えるとは仮定しない。
- 専用の引き継ぎ書やSTATUS.mdは設けない。判断はREADME、変更理由と検証はコミット、未完了事項はIssueに残す。

## 自己レビューと対応（2026-11-07）

初期版をコード、形状生成、操作判定、配布物、検証の観点から再点検した。
「免責を付ければ十分」とせず、誤認につながる形状と未検証項目を残課題として扱う。

| 重要度 | 問題 | 対応と残る制約 |
|---|---|---|
| 高 | 球と管の重なりを解剖模型として扱うには精度が不足 | 左心室の心尖方向と先細りを調整。ただし中隔、弁、血管接続は未検証で、外観の完成とは判定しない。今後の素材候補は無料・会員登録不要という条件で検討 |
| 高 | 固定距離では縦長画面の横画角が足りず見切れ得る | モデル境界と縦横画角で距離を算出。5種類の画面比率、3方向の全頂点を計算で検証 |
| 中 | ピンチ、キャンセル、往復ドラッグをクリックと誤認し得る | ポインターID、移動履歴、複数指、キャンセルを追跡する判定へ変更 |
| 中 | 静止時にも連続描画して電池を消費する | 必要時のみ描画し、回転時だけフレームを継続。タブ非表示と操作開始で停止 |
| 中 | キーボードで任意方向に回転できない | 矢印キー操作と前面・背面・側面ボタンを追加 |
| 中 | WebGL喪失時に説明がなく操作できるように見える | 画面に再読み込み案内を表示し操作ボタンを無効化 |
| 中 | HTML単体ではThree.jsの完全なMITライセンスが付属しない | ライセンス全文をHTMLへ埋め込み、画面からも読めるように変更 |
| 高 | 初回の表示テストが実行されていない | ローカルはsocket制限で起動不可。GitHub Actionsで5件のブラウザーテストが成功し、PCとスマートフォン幅の保存画像を目視確認 |

## 検証状況

v0.2のビルドとNodeの8テストは成功。
幾何データの有限値、モデルの画角内配置、タップ判定、外部読込なし、ライセンス同梱を検証した。

PlaywrightはPC幅1440px、スマートフォン幅390pxと320pxで、オフライン起動、モード切り替え、部位選択、回転、拡大縮小、ピンチ、キーボード、静止時の描画停止、エラー表示を検証する。
画像はGitHub Actionsの`viewer-checks`成果物に保存する。
ローカル環境ではChromiumがsocket権限制限で起動できないが、[GitHub Actionsの実行42336490926](https://github.com/Panda4th/Human-heart-3D-model/actions/runs/42336490926)で5件のブラウザーテストが成功した（対象コミット `aecfa523`）。
PC幅1440pxの外観と刺激伝導系、幅320pxの刺激伝導系の保存画像を目視確認した。
画面の見切れや文字の重なりは確認されなかったが、外観は球と管による概形にとどまり、参考モデルと同等の品質とは評価しない。
実機iPhoneとSafariの確認、MSDモデルとの視覚比較、解剖学的形状の検証は別途必要。
