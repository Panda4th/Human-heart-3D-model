# 拍動中のブラウザー内処理時間（2026-11-12、Issue #17）

`main` の `e110a29` を対象に、拍動中のビューアをChromiumで動かし、フレーム処理と断面ラベルの遮蔽判定を計測した。
PR #40の静止時の測定とPR #41の拍動中の測定は、いずれもNodeで個々の処理を呼んだ値。
今回はブラウザー上で通常の拍動を再生し、選択を固定したまま、ビューアが実行した処理の経過時間を採取した。

断面の房室結節を選んだ条件ではラベルが断面で消え、全サンプルで遮蔽判定の呼び出しは0回だった。
洞房結節と「心房への広がり」は、どちらも1フレームあたり1回。
血流を重ねない条件で、「心房への広がり」は洞房結節より3回とも遮蔽判定に時間がかかった。
「心房への広がり」の遮蔽判定のp95は、血流の重ね表示オフで14.0〜20.2 ms、オンで20.9〜21.7 msだった。
この差には、測定した拍動位置や実行時の負荷のばらつきが含まれ得る。

描画呼び出しは `renderer.render` の呼び出しから復帰まで、描画準備は `drawFlow` が実行されたフレームでの経過時間。
コールバック間隔には、ビューアのフレーム処理の外で経過した時間も含まれる。
この環境では描画の完了や提示の時刻、実機GPUの処理時間、iPhone Safariでの性能は未測定。
断面のクリックも今回の計測範囲外で、静止形状でのNode計測はPR #40を参照。

## 計測方法と再現

ビューアのボタンでモードを切り替え、「実際の速さ」をオンにして拍動を開始した。
ビューアは1回のコールバックで拍動を進める時間を250 msに制限する。
採取したフレームには複数の位相が含まれるが、位相ごとのサンプル数は揃えていない。
断面は正面、スライダー0、刺激伝導系の重ね表示オンで固定し、選択部位と血流の重ね表示だけを変えた。
各条件を新しいブラウザーコンテキストで開き、開始後の24フレームを捨てて96フレームを採取した。
順番を変えて3回繰り返し、表には各回で求めた統計値の最小と最大を載せた。
計測前に選択状態を確かめ、採取したフレームについて、遮蔽判定の呼び出し回数、血流の描画準備の有無、複数の拍動位相を通過したことを検査した。

配布HTMLと通常のビルドがバイト単位で一致することを確認したうえで、同じビルド手順で計測点を挿入した一時HTMLを開く。
フレーム処理は `render` の入口から、次のフレームを予約する処理までの経過時間。
遮蔽判定の欄はラベル用の `pickHit` 1回の経過時間で、ラベル位置の更新などを含む `updateLabels` の内数。
コールバック間隔は、連続する `requestAnimationFrame` のタイムスタンプの差で、実際に画面に提示されたフレーム数は採取していない。
[requestAnimationFrameの仕様解説（MDN）](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)

```sh
npm ci
npx playwright install chromium
node scripts/measure-viewer-frame-cost.mjs > /tmp/viewer-frame-cost.json
```

既存のChromiumを指定する場合は `CHROMIUM_PATH` に実行ファイルのパスを設定する。
集計JSONには各回の条件別中央値、p95、最大値と描画バッファ寸法がある。
