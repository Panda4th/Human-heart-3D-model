# ヒットテストを表示中のメッシュだけに絞った前後比較（2026-11-12、Issue #17 / #21）

[拍動中の処理時間の記録](issue-21-beat-cost-2026-11-12.md)で、拍動中のフレームで最も重い処理はラベル遮蔽の光線（約7ms）だった。
原因を調べたところ、断面モードは元の壁（非表示）と切り口付きの複製（表示）を並べて持ち、光線は非表示の側の三角形も試験して、その結果を `isShown` で捨てていた。

## 変更

`src/viewer-state.mjs` の `pickHit` が、表示中のオブジェクトだけを `Raycaster.intersectObjects(…, false)` に渡す（`shownObjects`）。
祖先に非表示があるもの、自身が非表示のものは、子孫ごと飛ばす。表示中のオブジェクトの順序は、three.js の再帰（先行順）と同じ。
`isShown` による事後の判定は残した（冗長だが挙動を変えないため）。クリックとラベル遮蔽の両方が `pickHit` を通るので、両方が速くなる。

内部モード（スライダー0）で、`occluders` 25メッシュのうち10メッシュ（非表示の元の壁）、三角形では114,892面のうち50,650面（44%）が光線試験の対象から外れる（数え方は「再現」）。
three.js の `Mesh.raycast` は境界球と境界箱で早く打ち切ることがあるため、これは対象の三角形数で、実際に試験していた三角形数の減り方ではない。
等価性は、three.js の `Raycaster` が `raycast` の戻り値 `false` で子孫の試験を止める仕組み（`LOD` が使う）を、このモデルが使っていないことにもよる。

## 結果が変わらないことの検査

`tests/viewer-state.test.mjs` に等価性テストを足した（単体テストは66件から67件）。
変更前の `pickHit` の写し（非表示も含めて試験し、`isShown` で捨てる）と新実装を、6条件×270本の光線で比べ、戻り値（部位ID・距離・切り口かどうか・切り口の点）全体の一致を検査する。
条件は、外観（伝導系の重ね表示オフ／オン）、断面0（ラベル用の対象／クリック用の対象で重ね表示オン）、断面+0.5・−0.5（クリック用・重ね表示オン）。線の当たり判定幅は `src/main.js` と同じ。
切り口に当たる光線と、伝導系に当たる光線が比較に含まれることも検査する。
あわせて、`Mesh.raycast` の呼び出し数が断面0で0.8倍未満に減ること、外観でも減ることを検査する（外観では弁と乳頭筋が非表示）。
比較は正面の1視点、静止形状に限る。
測定スクリプトの切り口に当たった光線の本数は、変更前後で同じ（980／962／915本）。

## 限界

- Node（V8）の表はCPU時間。ブラウザー内の表は、デスクトップのChromiumとソフトウェアWebGLの値。GPU、iPhone実機の値ではない。
- ラベル光線の表は、断面に残る全ラベルを混ぜた分布。実ビューアは選択中の1ラベルだけを判定する（拍動中の記録の説明を参照）。
- 三角形1枚あたりの試験の費用は変えていない。残る費用は表示中のメッシュの三角形（約64,000面）の試験で、境界箱による先行判定や間引きは未実施。
- 実機で滑らかになったとは言えない。この環境でもコールバック間隔は変わっていない。変更の確認は、処理時間の減少と、判定結果の一致までに限る。
- ローカルのChromiumテストは、Playwrightが想定する版（1254）ではなく、環境に入っている版（1243系、153.0.8010.12）で実行した。CIは別途成功している。

## 再現

変更前後を交互に2回ずつ実行した（既存の記録は3回）。

```
git checkout 7777407 && npm ci && node scripts/measure-beat-cost.mjs > before.json
git checkout 08fc2cd && node scripts/measure-beat-cost.mjs > after.json
node --test tests/viewer-state.test.mjs
```

メッシュ数と三角形数は、`tests/viewer-state.test.mjs` と同じ構築（`createAnatomy`、`createCrossSection(…).setEnabled(true)`）の後に、次のように数えた。

```js
const occluders = [...parts.values()].filter(g => g.userData.kind !== 'conduction');
const shown = o => { for (; o; o = o.parent) if (!o.visible) return false; return true; };
let meshes = 0, visible = 0, triangles = 0, visibleTriangles = 0;
for (const g of occluders) g.traverse(o => {
  if (!o.isMesh) return;
  const n = o.geometry.index.count / 3;
  meshes++; triangles += n;
  if (shown(o)) { visible++; visibleTriangles += n; }
}); // 25, 15, 114892, 64242
```
