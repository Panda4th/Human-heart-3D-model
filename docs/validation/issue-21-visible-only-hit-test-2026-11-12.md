# ヒットテストを表示中のメッシュだけに絞った前後比較（2026-11-12、Issue #17 / #21）

[拍動中の処理時間の記録](issue-21-beat-cost-2026-11-12.md)で、拍動中のフレームで最も重い処理はラベル遮蔽の光線（約7ms）だった。
原因を調べたところ、断面モードは元の壁（非表示）と切り口付きの複製（表示）を並べて持ち、光線は非表示の側の三角形も試験して、その結果を `isShown` で捨てていた。

## 変更

`src/viewer-state.mjs` の `pickHit` が、表示中のオブジェクトだけを `Raycaster.intersectObjects(…, false)` に渡す（`shownObjects`）。
祖先に非表示があるもの、自身が非表示のものは、子孫ごと飛ばす。表示中のオブジェクトの順序は、three.js の再帰（先行順）と同じ。
`isShown` による事後の判定は残した（冗長だが挙動を変えないため）。クリックとラベル遮蔽の両方が `pickHit` を通るので、両方が速くなる。

内部モード（スライダー0）で、`occluders` 25メッシュのうち10メッシュ（非表示の元の壁）、三角形では114,892面のうち50,650面（44%）が試験から外れる（プロファイルは本記録の再現手順2）。

## 結果が変わらないことの検査

`tests/viewer-state.test.mjs` に等価性テストを足した（単体テストは66件から67件）。
旧実装（全オブジェクトを試験してから非表示を捨てる）と新実装を、外観・断面0・+0.5・−0.5の4状態、各504本の光線で比べる。
外観の全光線と、断面で切り口に当たらなかった光線は、部位IDと距離が一致する。切り口に当たった光線は `cutFace` が変わっていないため比較から外した。
あわせて、`Mesh.raycast` の呼び出し数が断面0で0.8倍未満に減ること、外観でも増えないことを検査する。
測定スクリプトの切り口に当たった光線の本数は、変更前後で同じ（980／962／915本）。

## 限界

- Node（V8）のCPU時間。ブラウザー内、GPU、iPhone実機の値ではない。ブラウザー内の測定（`scripts/measure-viewer-frame-cost.mjs`）は変更後に再実行していない。
- ラベル光線の表は、断面に残る全ラベルを混ぜた分布。実ビューアは選択中の1ラベルだけを判定する（拍動中の記録の説明を参照）。
- 三角形1枚あたりの試験の費用は変えていない。残る費用は表示中のメッシュの三角形（約64,000面）の試験で、境界箱による先行判定や間引きは未実施。
- 実機で滑らかになったとは言えない。変更の確認は、CPU時間の減少と、判定結果の一致までに限る。

## 再現

```
git checkout 7777407 && npm ci && node scripts/measure-beat-cost.mjs > before.json
git checkout <この変更のコミット> && node scripts/measure-beat-cost.mjs > after.json
node --test tests/viewer-state.test.mjs
```

1. 計測は3回ではなく変更前後を交互に2回ずつ。
2. メッシュ数と三角形数は、`createAnatomy` と `createCrossSection(…).setEnabled(true)` の後に `occluders` を走査し、祖先を含めて表示中のものを数えた（使い捨てスクリプト、未保存）。
